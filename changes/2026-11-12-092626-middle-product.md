### jxcg_core
- 新增 `zhongjian` 模块：
  - `ZhongjianIndex`：由 Catalog 派生「产物 ∩ 材料」集合；同物品多配方取 `(dengji, id)` 最小者；
    `is_zhongjian_peifang` = 产物非空且全部为中间产物。
  - 递归展开：每批成本 = Σ(材料需求 × 单价) + 精力×精力单价 + 制作费（**不含保管费**）；
    单位成本 = `HALF_UP(每批成本 × 2×2^20 / Σ(quanzhong×(min+max)))`；单位链路精力同理；
    金额全程 i128 整数，最后 HALF_UP 到铜，禁止 f64 参与金额。
  - 兜底：无产出配方 / 期望产出为 0 / 成环（递归栈检测）/ 深度 > 8 / 溢出
    → 该行回退 `jiage` → 商店价 → 缺价；`laiyuan` = `hangqing` / `shoudong` / `shangdian` / `quejia`。
  - memo：单位成本缓存（含缺价 id 列表；memo 命中时重复冒泡缺价，避免排行批量漏报）。
- `craft`：新增公开 `Calculator`（请求级索引 + memo，排行复用）；`jisuan` 单次入口签名不变。
  顶层自制行按「单位成本 × 顶层需求」计入 `chengben_cailiao`，`chengben_zhongjian` 仅展示不重复加总；
  `jingli`/`chengben_jingli`/`zhizuofei` 只算最终配方自身；`zong_chengben` 严格 = 四项之和；
  `zhongjian_zizhi=false` 时完全不展开、`shoudong` 也不生效（与旧实现逐字段一致的回归测试）。
  中间明细 `ZhongjianMingxi.cailiao` 的数量按「顶层需求 / 每批期望产出」折算（展示口径，HALF_UP）。
- `rank`：一次请求只建一次索引/memo；`baohan_zhongjian=false` 时跳过「只产中间产物」的配方，
  true 时包含并标记 `zhongjian=true`；排序规则不变（缺价末位 → 指标降序 → id 升序），limit 排序后截断。

## 关键决策
1. 采用 Lead 裁决的方案 B：`jiage` 全量价格 + `shoudong` 手填集合；展开判定只看 `shoudong`，
   与「行情价存在」解耦（否则行情价会把中间产物全部变成「采购价」，功能失效）。
2. 单位成本先 HALF_UP 到铜，再乘顶层数量（DTO 冻结语义「单位自制成本 × 数量」）；
   每个中间产物层只取整一次，避免跨层累计误差。
3. 中间产物自制不计保管费；最终配方保管费照旧。
4. `zhongjian_zizhi=false` 为严格旧行为（含 `shoudong` 无效）；旧口径下 `jiage` 可继续只传所用价格。
5. 中间明细的 `cailiao` 为「顶层需求折算」的展示数据，不参与成本加总（成本以 `danjia × shuliang` 为准）。
