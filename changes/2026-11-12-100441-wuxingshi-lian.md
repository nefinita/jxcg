## 算法口径（已与 Lead 给定金标准核对）
- 主产物每次期望产出 = Σ(bp/10000 × shuliang)，合成次数 = 需求 / 该值；失败余量只放大次数、不额外损失材料。
- 只按方案内 `[[hecheng]]` 递归；无配方物品视为采购原料（行情/手填 > 商店价 > 缺价）。
- 副产物 = 非主产物结果槽（含更高阶产物与八级意外产出）：期望量 = 次数 × bp/10000 × shuliang，
  按行情/商店价折价冲抵成本；不冲抵中间产物需求（与 592.95 一级石 / 581.35 精力 / 67.9704 金加工费一致）。
- 合 6 出 8 级：仅当目标为六级时，将六级配方中 `5_24430` 槽 bp 用 `req.baoji_bp` 覆盖（None=数据值，0=忽略），
  bp clamp 0..10000，按「额外产出」计入副产物收益。0.05% → +128,076 铜（约 12.8 金）/颗；0.1% → +256,153 铜（约 25.6 金）。
- 金额：期望量全程 f64，结果字段**一次性 HALF_UP 到铜**；`zong_chengben = 材料 + 精力折金 + 加工费 − 副产物收入` 严格成立。
  `cailiao`/`fuchanpin` 行内的数量/小计为展示口径（各自取整），总额字段全局一次取整（行与总额允许 ≤1 铜差异）。
- `jingli = round(Σ 次数×每步精力)`；`danjia = round(zong_chengben / shuliang)`；
  `baobenjia` 用 `fee::baobenjia(danjia)` 由单位净成本反推（含 5% 手续费）；
  `lirun = 市场价×数量 − 5% 手续费 − 净成本`（保管费默认 0，DTO 无该字段）。
- 排序：采购原料/副产物按物品 id 升序；步骤按 data 文件顺序（3/4/5/6）；`quejia` 排序去重。
- 错误：方案不存在 / 目标无配方 / 主产物概率缺失 / 成环或深度 > 16 / 负数价格或精力单价 / 件数 0 → 中文 Error。

## 需要 Lead 在 src-tauri 注册的命令
- 命令名建议：**`calculate_wuxingshi`**（与前端 `api/commands.ts` 对齐）。
- 建议签名（放到 `commands/calc.rs`，用现有 `AppState` 目录缓存）：
  ```rust
  #[tauri::command]
  pub fn calculate_wuxingshi(
      app: tauri::AppHandle,
      state: tauri::State<AppState>,
      req: WuxingshiLianRequest,
  ) -> Result<WuxingshiLianResult, String> {
      let catalog = state.catalog(&app)?;
      jxcg_core::wuxingshi::jisuan_lian(&catalog, &req).map_err(|err| err.to_string())
  }
  ```
- `mubiao_wupin_id` 按冻结契约由前端传（默认 `5_24428` 六级），后端不做隐式默认。
