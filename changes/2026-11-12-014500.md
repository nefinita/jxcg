# JX3BOX 全量数据导出 + 行情缓存/降级（market-data / task-3）

## 改动与原因

- 新增 `server_tools/jx3box-export`：从 JX3BOX 抓取 5 技艺配方目录/详情、物品、NPC 商店价、服务器列表，
  生成 `data/*.toml`（保持既有 schema）。实测 40.5s / 2405 次请求 / 0 失败，可重复运行；
  支持 `--cache` 复用原始 JSON、`--offline`、`--limit`、`--concurrency`(≤6)、`--timeout`。
- `data/` 从样例替换为全量：配方 **1036**（烹饪 89 / 制药 62 / 缝纫 221 / 铸造 253 / 梓匠 411）、
  物品 **1361**（材料 394 / 成品 961 / 五行石 6；含 NPC 商店价 74 条）、服务器 22；总体积 608KB。
  `data/README.md` 记录来源、统计、口径与重新生成方式。
- `crates/jxcg_market` 完整化：
  - `cache`：用户数据 `hangqing/{服务器}.toml` 读写（手动覆盖 `shoudong=true` 优先）；
  - `refresh`：并发拉取 + 进度回调 + **last-known-good**（失败不覆盖缓存、回落旧价并计数 `jiangji`）+
    手动价保留 + 缺价统计；`fetch_xingqing` 单物品接口；
  - 21 个离线测试（录制 JSON fixture）+ 1 个 ignored 真联网冒烟（已通过，2 成功 / 0 失败）。
- 上游 server 参数必须传**服务器中文名**（拼音 id 会返回空 prices 被误判缺价），刷新入口内部已处理。

## 关键决策

- 数据与代码分离：静态配方/物品随包，行情是用户数据（应用数据目录，不进仓库）。
- 刷新失败不删旧价（断网可用），手动覆盖永不被自动价覆盖（对齐 PLAN D2）。
- 物品分类按 JX3BOX Genre/SubType 粗分，84 条不确定项标 `laiyuan="jx3box(粗分)"`。

## 回归验证

- `cargo test -p jxcg_market -p jxcg_core`：21 + 1 ignored（联网冒烟）、56 + 6 全绿。
- `cargo fmt/clippy -p jxcg_market -p jx3box-export` 干净；`data/` 可被 `jxcg_core::store` 加载。

## 遗留

- 五行石规则（manufacture 接口不含）仍为手工样例，待实机校准；`dui`（堆叠数）上游无接口，暂无数据。
