# 核心计算引擎加固（P1-P2）：金额 / 费用 / 配方 / 排行 / 五行石 / 数据装载

> 作者：core-engine（task-1）；时间：见文件名。

## 改动内容

### jxcg_api（DTO 契约，向后兼容）
- `PaihangRequest` 新增 `#[serde(default)] pub baohan_quejia: bool`：
  默认 `false` = 缺价配方排除（保持旧行为）；`true` 时缺价行保留、`PaihangRow.quejia = true` 且排在末尾。
- 细化 `JisuanRequest.cishu/guadan_cishu`、`ZhuanhuanRequest.cishu`、`ZhuanhuanResult.qiwang_cishu/zong_chengben/shouru`、
  `NetResult.daoshou` 等字段注释，冻结语义。
- 新增 DTO 契约测试（`serde_json` dev-dependency）：枚举 snake_case 协议名、各请求可选字段的 serde 默认值、
  可选字段缺省、`Catalog`/结果类型 JSON 往返。**无字段改名/删除/类型变更，Tauri 命令签名不变。**

### jxcg_core（计算引擎）
- 新增内部 `math` 模块：i128 取整（HALF_UP/CEIL/有符号）与乘加/转 i64 的中文溢出错误，避免浮点累计误差。
- `money`：`parse_jin` 支持 `-` / `负` 前缀与完整 i64 往返（含负利润、`i64::MIN`）；
  精度（砖 8 位/金 4 位/银 2 位/铜 0 位）、千分位、符号重复、溢出、非法输入全部中文报错。业务入口仍拒绝负售价/成本/单价。
- `fee`：抽出 `validate_shouxufei`（`0 <= shuilv_bp < 10000`、`baoguanfei >= 0`），
  net/baoben/craft/convert 统一校验；HALF_UP/FLOOR/CEIL 边界与到手可为负；保本价「指数扩上界 + 二分」并保持逐铜最小性。
- `craft`：材料价优先级 行情/手填 > 商店价 > 缺价（缺价按 0 计、`quejia` 排序去重）；
  期望产出按 2^20 权重（不重新归一化）；期望收入/材料/精力/制作费/保管费用 **i128 精确累加、最后一次性 HALF_UP 到铜**；
  批量 `cishu>=1`、保管费 = 单次 × 挂单次数 × 批量（`guadan_cishu=0` 不计）；利润率万分比整数 HALF_UP；保本单价按期望产出折算。
- `rank`：三种指标降序 + 同值按配方 id 升序兜底；缺价默认排除，`baohan_quejia` 时置标记并排在有效行之后；`limit` 在排序后截断。
- `convert`：修正口径为「`cishu` = 目标成功次数」，期望投入 `cishu/p`、期望收入 `cishu × 高阶石单价`、成本四舍五入到铜；
  成功率 clamp 到 1..10000（0/负 → 0.01%，>100% → 100%）；缺价 fallback 商店价。
- `store`：缺文件/坏字段错误带文件名与中文提示；`JXCG_DATA_DIR` 设置但无效时报错（不静默回落）；
  新增 `resolve_data_dir_strict` 与 `resolve_data_dir` 纯逻辑注入版本；新增 `validate_catalog`（重复 id、产物 min>max）。
- 新增 `crates/jxcg_core/tests/golden.rs`：PLAN §6.2/§6.4 金标准（净收入/到手、配方利润 139.2 金、批量线性、保本价 ±1、负利润往返、五行石 1/p、排行缺价）。
- 保本单价额外用「暴力扫描」校验期望产出为非整数（2.5 件）时仍逐铜最小。

## 为什么
骨架存在需要修正的口径/健壮性问题：
1. `convert` 原实现「成本 ×1/p、收入 ×p」自相矛盾（cishu 语义不清），与 PLAN §6.3 不符；
2. `craft` 逐槽 f64 round 会累计误差，且 `u32×u32` 中间积可能 i64 溢出 panic；
3. 金额解析不支持负数，`format_tong → parse_jin` 对负利润无法往返；
4. `PaihangRow.quejia` 字段没有入口可用（缺价行永远拿不到），前端无法提示缺价配方；
5. `JXCG_DATA_DIR` 配错会静默回落，坏数据（重复 id/min>max）会让排行榜结果不可信；
6. 商户/编排层需要稳定、可测试的中文错误。

## 关键决策
1. **五行石 `cishu` = 目标成功次数**（与 Lead 确认）：期望投入总次数 `qiwang_cishu = cishu × 10000 / chenggonglv_bp`，
   期望收入 = `cishu × 高阶石单价`；与 craft 的「产出侧」口径一致。
2. **取整一次性**：期望收入/成本先 i128 精确累加，最后 HALF_UP 到铜；费率手续费仍按 PLAN §6.2 的 HALF_UP 单独取整。
3. **利润率分母 = `zong_chengben`** = 材料 + 精力 + 制作费 + 保管费（DTO 各部分之和）。
   PLAN §6.4 的 13.9% 示例若按不含保管费的 1000 金算为 13.92%，按含保管费算为 13.91%，仅展示层面差 1bp；
   本实现保持骨架既有 `zong_chengben` 定义（含保管费），前端展示 13.9% 不受影响。
4. **缺价**：按 0 计入成本/收入并汇总 `quejia`（排序去重），排行默认排除；缺价行利润指标不可信，故包含时一律排末尾。
5. **金额可负**：`money` 只做通用编解码（负利润可展示/往返）；售价、成本、单价、精力单价、制作费、保管费、金币消耗等业务入口一律拒绝负数。
6. **材料来源标记**：`hangqing`（行情/手填由上层合并进 `jiage`，无法区分）、`shangdian`、`quejia`。
7. `JXCG_DATA_DIR` 一旦设置且非空即视为显式指定，指向无效目录 → 中文错误；未设置时才走 exe/data → debug 仓库 data。
8. `craft` 的 `cishu=0`/`convert` 的 `cishu=0` 报错（不再静默当 1）；`guadan_cishu=0` 合法（不计保管费）。
